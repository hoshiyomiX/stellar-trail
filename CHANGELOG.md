# Changelog

## v3.6.9 — 2026-09-28

Explorer correctness release — `explorer.sh --ensure` audited end-to-end and made content-exact, the upgrade-path activation gap closed in bootstrap, and the UI restyled around a guard-status hero with a content-summary Session Task list.

- **explorer.sh v1.5 — the `--ensure` audit, fixed.** Five findings from the edge-case matrix: (1) the v1.4 process-freshness check compared mtimes (`explorer.py` newer than the pidfile) — ambiguous at same-second writes and dependent on `cp -p` semantics through the deploy chain — replaced by a CONTENT STAMP: the server writes the md5 of its own source to `.zscripts/explorer.code-stamp` at startup (before serving), and `--ensure` restarts any live server whose stamp no longer matches the deployed file; a missing stamp = a pre-v1.5 server = one migration restart. (2) The restart path used `pkill; sleep 1` — a server ignoring SIGTERM could answer healthz on its own dying socket and silently skip the restart — replaced by `kill_wait` (TERM, poll up to 5 s for death, then KILL), used by sync_fresh and auto_deploy too. (3) `--stop` killed the pidfile pid blindly — a recycled pid was collateral damage — now guarded by a `/proc/<pid>/cmdline` identity check (the pattern pkill still catches the true server). (4) A live server with a missing pidfile (externally deleted) lost the freshness anchor forever — `--ensure` now heals it with a restart (safe: the server writes pidfile + stamp before serving). (5) The start health verdict gets one +2 s retry for slow cold starts. `--status` reports the stamp-based process/code freshness.
- **bootstrap-sandbox.sh — deploy-time explorer activation (closes the upgrade-path gap).** dev.sh covers BOOT, the watcher covers DEATH (health-fail only — an old-but-healthy server never triggers it); the DEPLOY moment had no trigger: update-skill's step [4/4] synced the `.zscripts` files via bootstrap and stopped, leaving the running process on the previous release's code (observed live at the v3.6.7 first-hop: pid 9082 survived the swap, `/api/tasks` 404-ed until a manual `--ensure`). Bootstrap now runs `explorer.sh --ensure` at the end of every invocation (output to the boot.log ledger; a failure never fails bootstrap — service issue, not persistence state), so every path that deploys explorer assets also activates them.
- **explorer.py v1.4 — guard + resets API, code stamp.** At startup the server writes the content stamp; `/api/files` gains a `guard` block (live vs canonical skill version + in-sync flag, watcher liveness/pid, THIS process's code freshness via the stamp, Next.js stand-down flag) and a `resets` block parsed from the persistence-layer ledger logs — dev.sh boots (session resets), `SKILL RESTORE … restored from the canonical snapshot` events (the version-gate "skip" lines are not restores), repo-snap auto-applies, explorer restarts, freshness/heal restarts, sync-fresh refreshes — each with count + last timestamp (last-1-MB scan window; missing logs = empty counters, never an error).
- **Explorer UI v5.1 — guard duo hero + content-summary task list.** The page opens with a hero of two large tonal tiles — **Guard Status** (live version, watcher dot, canonical in-sync / drift line, explorer code-current / restart-pending line, stand-down notice) and **Session Reset & Restore** (last dev.sh boot as a relative timestamp + boots / skill restores / explorer restarts / archive refreshes counters + absolute last-reset footer) — followed by the **Session Task list as a full-width section**: active tasks as a responsive card grid carrying expandable content summaries (4-line clamp + show more/less), sealed rows with outcome + artifact preview. The file inventory follows with a compact stats header (files · size · roots) and a wider card grid (the old sticky task column and the 5-tile stat row are retired; the guardian tile's data lives in the hero). All v5.0 features carry over: adaptive theme, 200 ms debounced search, filter chips, segmented sort, copy-path, preview dialog with `?dl=1`, chunked lazy render, 10 s polling + focus refresh, reduced-motion opt-out. A v5.0 regression is fixed: the sealed-task artifact preview buttons had no click delegation and did nothing.

## v3.6.7 — 2026-09-27

Architecture release — ONE install flow, English-everything, and the repair chain retired. Scope locked by the owner across four points: full English rewrite, fresh+upgrade install simulations, a single installation flow with no fallbacks, and a final skill-creator audit.

- **`npx skills add hoshiyomiX/stellar-trail` is now the ONLY install flow.** Installing, re-installing, and repairing this skill all run the same command — there is no parallel installer, no fallback route, and no silent repair. `update-skill.sh` is rewritten as a thin wrapper around it (242 → lean): a debounced origin check (24 h, `.zscripts/.update-check.last`; `--force` pierces, `--check` dry-runs, `--status` offline) and, when the origin is newer, a verified override in four printed steps — `[1/4]` run the single install command, `[2/4]` verify the installed version, `[3/4]` verify the package manifest of the updated installation, `[4/4]` arm the persistence layer via `bootstrap-sandbox.sh $BOOTSTRAP_ARGS` (default `--ensure --with-explorer --with-snapshot`; env override `STELLAR_UPDATE_BOOTSTRAP_ARGS`). The wrapper self-copies and re-execs before touching the tree and normalizes modes to 0644, and treats offline as a one-line report with exit 0 — M0 never depends on the network. Every alarm the package can raise (watcher integrity alarm, release-file guard, M0 version-sanity alarm) prints this exact command as the remediation. The pre-refactor `swap_tree`/`rsync --checksum` machinery is superseded by this architecture: the skills CLI performs the install; the wrapper verifies what landed — one installer, one source of truth, zero silent repairs.

The evolution history and every incident that shaped it stay preserved in Appendix A; the standalone-helper doctrine's `version_lt()` controlled copy shrinks from a trio to exactly two (`update-skill.sh` + the bootstrap generated-hook gate).
