## v5.4.9 — 2026-10-25 · explorer UI v4.4: reconnect machinery removed + mobile header fit + R2 gate-battery daemon hygiene (owner order — Task 45, ref #44)

**Why — the owner accepted the Task 44 audit verdict (the explorer stack exonerated at every layer; the 3-29 s stalls are browser-to-ingress platform-edge delays correlating 1:1 with concurrently-active agent sessions) and ordered the 4-item follow-up — apply fix R2, remove the reconnect feature, fit the header card to mobile, audit before push:** the reconnect machinery was built for a hang class the audit proved is NOT the UI's, and its escalating backoff (up to 60 s) made recovery FEEL slow exactly when the owner was watching; the header clipped sideways on phone-width viewports; and the gate battery itself was leaking fixture watcher daemons (the R2 stray class that audit had to reap by hand).

**What shipped:**

- **UI v4.3.1 -> v4.4 — the reconnect machinery is REMOVED (owner order #2):** no failure backoff (the 10-20-40-60 s escalation is gone), no reconnecting chip (the element no longer exists in the DOM), no visibility/focus/online wake probes. One steady self-scheduling loop polls every 10 s win or lose — recovery is simply the next successful poll (self-heal, no user action, worst case one cadence tick), and the manual Rescan button + error-card Retry remain the user-driven paths. KEPT — the freeze fixes (removing these would resurrect the v4.2 total-freeze class reproduced in this same fixture): engine-independent deadlines (AbortController + Promise.race backstop), the in-flight poll guard, the no-abort 3-failure auto-poll breaker (on engines that cannot abort, Rescan IS the recovery path), and the 8 s boot watchdog. Footer wording is now steady-retry honest: retrying automatically every 10 s / automatic retry paused on this engine (tap Rescan to retry).
- **Mobile header fit (owner order #3):** at <=640 px the app bar wraps to two rows — logo + title + action buttons on top, the version + clock chips below, the title truncates with an ellipsis; a single 56 px row could not hold 7 items at 360-400 px and clipped/overflowed sideways. The chip removal (order #2) also shrinks the bar. explorer.py v1.7 / launcher v1.5 untouched — pure client-side change.
- **R2 (Task 44 recommendation, owner order #1) — gate-battery fixture-daemon reaping, trap-based:** every daemon-spawning battery script now tears its fixtures down on ANY exit path (EXIT/INT/TERM): task21-hooktest.sh — the proven 6-stray source, whose bootstrap runs armed watchers in two scratch projects with previously NO teardown at all — now stops both watchers, kills pidfiles, and carries a scratch-path pkill fallback; task37-hangtest.sh traps its 4-port hangserver + browser session; task13-validate.sh traps the B-group watcher; task20-gaptest.sh and task23-guardtest.sh trap their scratch watchers; task30-validate.py gained a SIGTERM-to-finally shim. Working-scripts side (the battery is release evidence, not shipped skill payload); verified by a post-battery daemon census (zero fixture strays).
- **task37-hangtest.sh rewritten for the v4.4 contract (38 checks):** the reconnecting-chip and wake-probe assertions are replaced by — chip ABSENT at every sample, honest not-answering footer, steady-cadence socket bounds (<=1 open on the modern engine), SELF-HEAL recovery within one 10 s cadence of the origin returning (no focus event fired — proving the steady loop alone reconnects), manual-Rescan recovery on the no-abort engine class (the designed path there), build markers UI 4.4, and zero page errors across the matrix. The v4.2 and v4.3-noAC freeze controls are untouched frozen copies — the reproduction power of the fixture is preserved.
