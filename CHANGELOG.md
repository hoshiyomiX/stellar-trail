# Changelog

## v3.6.6 — 2026-09-26

Feature release — auto-update before the phases begin, a dashboard explorer UI, and the controlled copy becomes a trio.

- **Activation rule 15 + `scripts/update-skill.sh` — auto-check for updates before the phases begin.** This closes the package's oldest freshness gap: a healthy-but-outdated installation (healing deliberately refuses to upgrade, and crash-safe migration only covers upgrades someone remembers to run). At M0 — immediately after `bootstrap --ensure`, before the first phase — the protocol now runs `update-skill.sh --ensure`: it queries the origin (GitHub, the sole distribution channel, read publicly without any token) at most once per 24 hours (debounced via `.zscripts/.update-check.last`; `--force` pierces, `--check` dry-runs, `--status` reports offline), and when the origin tag is newer it force-updates through a **verified override, never a blind pull**: shallow staging clone, full SHA-256 manifest verification, a tag≡content assert (a hijacked tag carrying different content aborts hard), an anti-downgrade assert, then a swap in the crash-safe order the resilience playbook prescribes (canonical first, class-A vaults, working install last), per-target rollback backups, the watcher restarted from the new canonical, and `bootstrap --ensure` re-run — install identity files (`_meta.json`, `.clawhub/`) are never overwritten, the script self-copies to a temp file before swapping (never overwriting the file it is executing), and offline is a printed one-line report with exit 0 so M0 never depends on the network. Every installation step prints to stdout (`[1/7]`…`[7/7]`) so the user stays informed and can follow up.
- **Explorer UI v4.0 — Dashboard.** The bundled `explorer-ui/index.html` is reworked from a 69,324-byte Material-3 card grid into a **29,441-byte dashboard** (−57.5%): a category sidebar with per-category counts (collapsing to horizontal chips on narrow screens), a statistic-card row with the guardian card folded in (version, watcher, last heal — hidden when the skill is not installed), and a main file table (name + condensed breadcrumb, category badge, size, relative time, actions). Core features kept: live search with 200 ms debounce, dynamic category filter, per-row copy-path with toast, preview dialog with `?dl=1` download, adaptive theme with persisted toggle, focus refresh, loading/empty/error states. Simplified: column-header sort with a plain direction indicator, chunked render (first 200 rows + "Muat lagi") — IntersectionObserver and per-card quick-download retired. Zero-dependency, `lang="id"`, API contract unchanged (`explorer.py` untouched).
- **Standalone-helper doctrine: the controlled copy is now a TRIO.** `update-skill.sh` ships the package's third byte-identical `version_lt()`; Appendix B of the resilience playbook and all three controlled-copy annotations now name the trio (R5 audit T63: change all three together, never consolidate).
- **Protocol wiring:** Activation rule 15 + M0 chain step + Unified Self-Audit checklist item + bundled-scripts table entry + quick-reference card + Penjelasan rationale; `references/environment-resilience.md` gains §9 (auto-update doctrine: trigger/debounce, verified-override semantics, §8 swap order, identity protection, offline-first) with a TOC entry; `references/task-files-explorer.md` gains §5d (UI v4.0 contract).
- **Final audit with skill-creator (latest installed version — mtime 2026-03-14, identical to the Task 63/66 audits; no newer release exists — verified honestly again this session).** Structural: **8 PASS / 0 FAIL / 1 documented SKIP** (glm CLI absent; description 1022/1024 unchanged). Behavioral paired eval (hermetic, both arms bound to isolated fixtures, same continuation-quarantine scenario as Task 66 with versions raised + a new rule-15 assertion): with-skill **7/7 (100%)** vs baseline **3/7 (43%)**, delta **+0.57** — the baseline still passes the semantic core (memory restore, quarantine intent, Indonesian) but fails the structural guarantees (protocol banner, phase markers, active-table resolution discipline, and the new rule-15 update check); the delta remains deterministic structure and auditability, now covering the auto-update discipline too.

## v3.6.4 — 2026-09-25

Release-file guard for the non-manifest release files — from the package's own internal audit (Task 63: orphan / dead-code / redundancy audit + skill-creator final audit; verdict: very clean package, the one structural blind spot sat outside it).

- **watcher.sh v1.7 → v1.8 — release-file guard (audit R1).** `skill-card.md` and `assets/integrity.sha256` are release files that live outside the SHA-256 manifest by construction (a manifest cannot hash itself; the skill card is the version source for the manifest generator). Across four post-boot incidents on the reference sandbox (three deletions and one reversion to version-stale content — all traced via millisecond mtime forensics to the platform's skill-manager layer reconciling the install at boot) no bundled layer ever noticed: `heal --check` kept reporting CLEAN while a release file was missing or stale. The daemon now checks existence and version freshness of both files on every 30-second cycle and auto-restores them from the freshest class-A vault whose card matches the shipped release version (older and newer vault cards are both skipped — anti-downgrade by construction; version upgrades remain the release process's job), with a 10-minute retry debounce and a silent no-op on consumer installs without a canonical copy. Vault candidates are project-relative first, then the reference-sandbox convention, overridable via `STELLAR_VAULTS`.
- **Fix: `--force-start` now really forces.** In v1.7 the daemon passed the pre-spawn gate but exited on its first loop iteration because the stop-flag was still in place; the production pattern had to be `--stop` + remove stop-flag + `--ensure`. `--force-start` now clears the lingering stop-flag itself.
- **Docs: table of contents refreshed to the skill-creator heading standard (audit R2)** — the old one-line TOC in `environment-resilience.md` had silently missed the section 8 added in v3.6.3; it is now a proper `## Daftar Isi` heading with the complete section list. **One out-of-package citation annotated (audit R3)** — the `drill_v357_restore.sh` receipt row now states the script is project-scope and not shipped in the package (the audit's only broken outbound reference).
- Project-level (outside the package): the three legacy directories (`stellar-trails/` — plural, a pre-rename remnant —, `workflow-memory-guardian/`, `task-files-explorer/`) were relocated out of the active `download/` namespace into `download/archive/` (audit R4); appeal evidence archives were left untouched.
- Verification: guard simulation **23/23 PASS** (healthy no-op, missing-card restore md5-identical from vault, version-stale card restore, missing-manifest restore, debounce without a fresh vault = exactly one attempt + honest failure, recovery log, consumer-layout silent skip, `--force-start` contract, idempotent ensure, stop-flag) + `enforce-gates --check-skill` 7/7 + lint 6/6 + manifest 26/26 + version-consistency gate.
