## Description:

Stellar Trail 🌠 is a mandatory six-phase execution protocol and persistent memory lifecycle **purpose-built for z.ai GLM agents (Super Z)**. Every human user message in every session runs the full workflow — classify (grounded in a canonical Ground Base Knowledge: type taxonomy, language rules, complexity calibration, ambiguity registry, environment truths), clarify in one batch, plan visibly before implementation, implement with per-artifact checkpoints (Phase 4 is progress-only), validate through five review layers, and report with auditable phase and memory markers. The memory half governs cross-session survival: a cold-boot restore (M0) reads the session snapshot and long-term memory before any substantive answer, checkpoints (M1) rewrite the snapshot atomically at every material state change in a fixed write order (snapshot first, ledger append last, one checkpoint per completed artifact), emergency compression (M2) protects the manifest under context pressure, and every session exit takes a full handoff (M3) — targeting ~95% cross-session context integrity with zero loss on critical items. Task-table hygiene makes stale-task pickup structurally impossible — a pickup decision table maps every signal (ACTIVE/WAITING/BLOCKED/STALE/SEALED/summary-only/empty-table continuation) to its action, the Active table holds only open-work rows each carrying a resume anchor, finished tasks exit through a mechanical Seal Ritual (S1–S4) that AUTO-SEALS in the same turn as the delivery report (acceptance presumed on delivery — owner order D14, v5.7.0; adjustments go via the UNSEAL pathway U1–U4) whose worklog verdict line makes seal detection greppable, unfinished tasks enter through a Resume Protocol (R1–R5) that continues at the recorded next step instead of restarting, sealed tasks are never resurrected, and platform continuation summaries are quarantined input — version-grounded against the memory files, never a work order. Enforcement is dual-track: terminal-verifiable rules run through the bundled gate script (enforce-gates.sh — a claimed-but-not-run gate is itself a violation), judgment rules stay as auditable text mandates. Activation is engineered and honestly measured: the frontmatter description is a trigger instrument (measured 8/10 on the reference first-turn battery — the best of any variant ever measured, wording-frozen since 2026-10-12 when two trimmed variants measured worse on the mixed greeting+task cell), a late mid-session load is a defined recovery event (Activation rule 6), and the bundled harness-hooks module seeds CLAUDE.md/AGENTS.md at the consumer project root for harnesses that auto-read them. The body is deliberately slim (~310 lines, English only) — execution mechanics the host platform already mandates are inherited, never duplicated — with deep procedures in four on-demand references; bundled tooling ships a one-command persistence layer for reset-prone container sandboxes (canonical copy + SHA-256-verified boot restore with a no-downgrade gate, a verify-only runtime watchdog, a restore-archive refresher, an external compliance audit, and an optional Task Files Explorer dashboard on the preview URL). There is exactly one install flow — `npx skills add hoshiyomiX/stellar-trail --skill stellar-trail -a openclaw -y` — no parallel installer, no fallback route, no silent repair, by design.
